# Телеметрия NeuroDeck (фаза 0 «Trust»)

> Статус: действует с v80 · Owner: @evgenijsimakov · Обновлён: 2026-09-29
> Реализация: [js/telemetry.js](../../js/telemetry.js) · Инструментация: [js/storage.js](../../js/storage.js)

## 1. Приватность (неизменяемый принцип)

- **Ничего не отправляется по сети.** Нет бэкенд-приёмника, нет запросов.
- Журнал живёт в памяти вкладки и в localStorage устройства.
- Хранилище: `neurodeck_diag_log` (кольцо событий), `neurodeck_diag_counters` (счётчики).
  Оба ключа с префиксом `neurodeck_` — стираются `resetAllData()` автоматически.
- Наружу журнал попадает **только** явным действием игрока/разработчика: `NDTelemetry.dump()`
  в консоли, копипаст в сообщение поддержки. Личные карточки и содержимое привычек в журнал
  не пишутся принципиально — только коды событий и технические числа.
- Будущий сетевой экспорт — только opt-in, отдельным решением (см. backlog).

## 2. API (глобальный `NDTelemetry`)

| Метод | Назначение |
|-------|-----------|
| `event(name, data?)` | событие в кольцо + счётчик; повтор того же имени < 2 c — только счётчик |
| `error(code, message, detail?)` | ошибка: немедленная запись в localStorage (переживает крах вкладки) |
| `counters()` | копия счётчиков `{имя: n}` |
| `ring()` | копия кольца (последние 200 событий) |
| `dump()` | `{ts, ua, href, counters, events}` — для поддержки/баг-репорта |
| `clear()` | стереть журнал и счётчики |
| `flush()` | принудительно записать в localStorage (pagehide/hidden — автоматически) |

Автоматически ловятся: `window.onerror` → `RUNTIME_ERROR`, `unhandledrejection` →
`UNHANDLED_REJECTION`, `pagehide`/`visibilitychange hidden` → flush.

## 3. Схема события

```json
{ "t": 1727600000000, "n": "cloud_push_ok", "d": { "n": 3, "ms": 812 } }
```

- `d` — только плоские примитивы: строки ≤200 символов (обрезка), числа, boolean;
  объекты приводятся к строке ≤60 символов; максимум 8 полей.

## 4. Каталог кодов ошибок

| Код | Источник | Смысл | Ожидаемая реакция игрока |
|-----|----------|-------|--------------------------|
| `STORAGE_WRITE_FAILED` | saveGameState | localStorage переполнен/сломан | тост «экспортируйте данные» |
| `LOAD_FAILED` | loadGameState | сейв не распарсился | авто-recovery-цепочка |
| `SAVE_FROM_FUTURE` | applySyncData | сейв более новой схемы | тост «обновите приложение» |
| `CLOUD_PUSH_FAILED` | pushCloudChunks | ошибка записи чанка/исключение | тост «часть данных не сохранена» |
| `CLOUD_PUSH_INTERRUPTED` | pushCloudChunks | таймаут 15 c / обрыв; meta не сдвинут | бейдж offline |
| `CLOUD_CHUNK_MISSING` | loadCloudChunks | чанка нет при чтении по meta | recovery-потоки |
| `CLOUD_CHECKSUM_MISMATCH` | loadCloudChunks | отпечаток не совпал: смешанное поколение/повреждение | recovery-потоки, «Данные повреждены» |
| `CLOUD_LOAD_TIMEOUT` | loadCloudChunks | облако молчит | бейдж offline |
| `RUNTIME_ERROR` | window.onerror | необработанная ошибка JS | — (диагностика) |
| `UNHANDLED_REJECTION` | unhandledrejection | необработанный Promise | — (диагностика) |

## 6. Envelope облачного сохранения v2 (`nd_meta`)

```json
{ "n": 3, "t": 1727600000000, "c": "9f2a1c77b04d5e83", "id": "m1abc2x9k3", "sz": 11842 }
```

- Чанки `nd_0..nd_(n-1)` по 4096 символов пишутся **первыми**; `nd_meta` — **последней**.
- `c` — канонический отпечаток `ndSnapshotChecksum` (2×FNV-1a 32-bit, UTF-16 коды символов,
  детерминирован между устройствами). `loadCloudChunks` сверяет его со склеенными чанками.
- `id` — идентификатор поколения (для логов; будущее — dual-generation rollback).
- `sz` — точный размер снапшота в символах.
- Отсутствие `c` (легаси) — проверка пропускается, чтение работает как раньше.
- Гарантии: обрыв пуша не сдвигает commit-pointer → старое поколение остаётся читаемым;
  частичная перезапись чанков новым пушем отсекается контрольной суммой (раньше —
  молча применялась как валидная).

## 7. Backlog (следующие итерации)

1. Opt-in сетевой экспорт diag-журнала (минимальный приёмник рядом с ботом).
2. Dual-generation в облаке (`nd_<saveId>_<i>` + хранение предыдущего поколения для
   облачного rollback) — требует пересмотра контракта `nd_0` в regression-T5M1.
3. Компрессия payload (CompressionStream с фоллбэком) — при подходе к лимитам CloudStorage.
4. Счётчикразмера сейва → предупреждение в UI при приближении к бюджету чанков (200).
5. Разбиение hot/cold state (карта мира в холодный слой) — вместе с Campaign 2.0.
