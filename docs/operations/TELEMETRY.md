# Телеметрия NeuroDeck (фаза 0 «Trust»)

> Статус: действует с v80 · Owner: @evgenidsimakov · Обновлён: 2026-10-01 (R2: envelope v3; R4: privacy-гейты приёмника)
> Реализация: [js/telemetry.js](../../js/telemetry.js) · Инструментация: [js/storage.js](../../js/storage.js)

## 1. Приватность (неизменяемый принцип)

- **Ничего не отправляется по сети.** Нет бэкенд-приёмника, нет запросов.
- Журнал живёт в памяти вкладки и в localStorage устройства.
- Хранилище: `neurodeck_diag_log` (кольцо событий), `neurodeck_diag_counters` (счётчики).
  Оба ключа с префиксом `neurodeck_` — стираются `resetAllData()` автоматически.
- Наружу журнал попадает **только** явным действием игрока/разработчика: `NDTelemetry.dump()`
  в консоли, копипаст в сообщение поддержки. Личные карточки и содержимое привычек в журнал
  не пишутся принципиально — только коды событий и технические числа.
- Будущий сетевой экспорт — только opt-in, отдельным решением (см. backlog).

## 2. API (глобальный `NDTelemetry`)

| Метод | Назначение |
|-------|-----------|
| `event(name, data?)` | событие в кольцо + счётчик; повтор того же имени < 2 c — только счётчик |
| `error(code, message, detail?)` | ошибка: немедленная запись в localStorage (переживает крах вкладки) |
| `counters()` | копия счётчиков `{имя: n}` |
| `ring()` | копия кольца (последние 200 событий) |
| `dump()` | `{ts, ua, href, counters, events}` — для поддержки/баг-репорта |
| `clear()` | стереть журнал и счётчики |
| `flush()` | принудительно записать в localStorage (pagehide/hidden — автоматически) |

Автоматически ловятся: `window.onerror` → `RUNTIME_ERROR`, `unhandledrejection` →
`UNHANDLED_REJECTION`, `pagehide`/`visibilitychange hidden` → flush.

## 3. Схема события

```json
{ "t": 1727600000000, "n": "cloud_push_ok", "d": { "n": 3, "ms": 812 } }
```

- `d` — только плоские примитивы: строки ≤200 символов (обрезка), числа, boolean;
  объекты приводятся к строке ≤60 символов; максимум 8 полей.

## 6. Envelope облачного сохранения v3 (`nd_meta`, R2 — очередь 4)

```json
{
  "v": 3, "g": "m1abc2x9k3", "n": 3, "t": 1727600000000,
  "c": "9f2a1c77b04d5e83", "id": "m1abc2x9k3", "sz": 11842,
  "prev": { "g": "m0zzz1q7x2", "n": 3, "t": 1727500000000, "c": "…", "id": "m0zzz1q7x2" }
}
```

- **Поколенческие ключи**: чанки нового поколения пишутся под `nd_<gen>_<i>` (по 4096
  символов) и физически не касаются ключей закоммиченного поколения — обрыв пуша
  не может смешать поколения (раньше чанки писались поверх живых `nd_0..`).
- **Commit-pointer**: `nd_meta` пишется **строго последним**; `g` = `id` = поколение.
- **Writer conflict**: перед записью meta делается CAS re-read — если другой писатель
  закоммитил поверх поколение с `t` свежее нашего на >10 c, свой коммит отменяется
  (`cloud_push_conflict`, свои чанки вычищаются). Мы свежее — коммитим, `prev`
  указывает на реально superseded поколение (цепочка не рвётся).
- **Rollback**: `prev` — дескриптор предыдущего поколения (`g` отсутствует = легаси-плоскость
  `nd_0..nd_(n-1)`). Читатель при повреждении текущего поколения (отпечаток/чанк)
  откатывается на `prev` (глубина 1, `cloud_rollback_used`); после ≥2 поколенческих
  коммитов в облаке живы ровно текущее + предыдущее.
- `c` — канонический отпечаток `ndSnapshotChecksum` (2×FNV-1a 32-bit, UTF-16 коды
  символов, детерминирован между устройствами); `sz` — точный размер снапшота в символах.
- **Легаси-чтение**: meta без `g` (envelope ≤ v2) читает плоские `nd_<i>` как раньше;
  отсутствие `c` — проверка пропускается. Первый v3-коммит поверх легаси держит
  `nd_0..n-1` как rollback-копию, surplus (`nd_n..nd_n+63`) вычищает.
- Fault-injection (только тесты/дебаг, в проде `ND_CLOUD_FAULTS` всегда null):
  `{chunk: idx|'any'}` — сбой записи чанка; `{meta: true}` — сбой commit-pointer;
  `{concurrent: <meta>}` — чужой коммит в полёте наших чанков. Контракты —
  `tests/cloud-envelope.test.js`, `tests/cloud-generation.test.js`.
- Обратная несовместимость (осознанная): СТАРАЯ версия приложения читает новое
  облако v3 как «повреждённое» (плоских чанков нет) и работает с локальными
  слоями; данные не теряются — свежий клиент читает всё.
