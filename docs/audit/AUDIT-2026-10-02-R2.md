## 2. MEDIUM

### M1. Бот: `/stop` теряется, напоминание приходит после отписки — **воспроизведено**
`bot/polling.js:157-178`: `schedulerTick` читает `chats.json` в начале, отправляет напоминания по одному через `await` и записывает **весь** снапшот в конце. Если во время тика пользователь шлёт `/stop` (`handleMessage` делает свой read-modify-write), тик затирает его отписку.

Репро на экспортируемых функциях (подмена API, без сети): у B до тика `daily`; B шлёт `/stop` → в файле `off`, бот отвечает «🔕 Напоминания выключены»; тик досылает B напоминание и пишет обратно `daily`. Это нарушение отписки, близкое к HIGH: пользователи жмут «спам», и Telegram ограничивает бота.

Тот же механизм даёт ещё дефект: `setInterval(schedulerTick, 30s)` (`:267`) не защищён от наложения тиков. Если тик длится дольше 30 с (таймаут SOCKS 15 с на каждую упавшую отправку), второй тик читает файл без `lastFire` и **дублирует** рассылку.

Исправление: один писатель (очередь или мьютекс), перечитывание записи чата перед сохранением, `lastFire` сохранять сразу после каждой отправки, не запускать тик, пока идёт предыдущий.

### M2. Бот: хранилище и транспорт без страховки
- `saveChats` (`:37`) пишет `chats.json` напрямую (`writeFileSync`). Если процесс упадёт во время записи, JSON будет битым, `loadChats` молча вернёт `{}`, и следующая запись сохранит только новые чаты — **все подписки потеряются без следа**. Нужна атомарная запись (tmp + `rename`) и отказ работать (а не `{}`) при битом файле.
- `api()` (`:103`): таймер есть только на SOCKS-рукопожатие. После CONNECT у HTTPS-запроса таймаута нет. Если ответ «висит» (обычное дело для прокси и DPI в РФ), `pollLoop` ждёт **вечно**: команды перестают обрабатываться, а процесс жив, поэтому systemd его не перезапустит. Нужны `req.setTimeout` и `sock.setTimeout`.
- Пользователь заблокировал бота (403) → ошибка только логируется (`:176`), повтор каждые 30 с всё окно догона (2 ч). Код 403 надо переводить в `mode: 'off'`.

### M3. Слой IndexedDB не работает как резерв — **воспроизведено**
`storage.js:2-12, 544-598`. Проба: сейв с картой лежит в IDB, localStorage пуст, загрузка страницы.
1. Диалог «♻ Найдено в IndexedDB» **не появляется** ни через 0,5, ни через 1,5, ни через 3 с. `loadGameState` выполняется синхронно в deferred-скрипте, а `indexedDB.open` ещё не успел вызвать `onsuccess` (`idb === null`), поэтому `loadFromIDB` сразу отвечает `null`. Вместо диалога показывается стартовая колода.
2. Игрок закрывает приложение → сохранение на `pagehide`/`beforeunload` (`app.js:5612-5613`) пишет пустой снапшот в IDB `latest`: **1 карта → 0**. Последний резерв уничтожается ровно в том сценарии, ради которого он существует.

Исправление: ждать открытия IDB (промис) перед проверкой; в `saveGameState` не перезаписывать IDB снапшотом с `FORGED.length === 0`, если там лежат карты (тот же принцип, что у `neurodeck_cards_backup`).

### M4. На новом устройстве стартовая колода перекрывает диалог импорта по ссылке — **воспроизведено**
Переход по `…/#<base64>` (сценарий «отправь себе в Избранное»): `importFromHash()` (`app.js:6221`) открывает «📥 Данные из ссылки». Через ~0,9 с `holdStarterDeck` (`:6269`) показывает стартовую колоду. У обеих модалок `z-index: 400`, старт-колода стоит в DOM позже, поэтому `elementFromPoint` над кнопкой «Подтвердить» возвращает `starterDeckList`. Игрок видит только старт-колоду. Если он её принимает (4 карты), диалог импорта всплывает потом; если принять и его, импорт перезапишет старт-колоду. Данные не теряются, но перенос выглядит как «ссылка не сработала». Взаимоисключение P0 1.3 закрыло облако, но не этот путь. Исправление: `holdStarterDeck` ждёт, пока открыт `confirmOverlay`, либо у `confirmOverlay` z-index выше модалок.

### M5. Разрушительные операции без точки отката
Импорт файлом или ссылкой, «Загрузить из облака», «Взять облако», глубокое восстановление: `applySyncData` → `saveGameState`. Один вызов перезаписывает **все пять слоёв сразу**: `neurodeck_backup`, `neurodeck_cards_backup`, IDB `latest`, облако, `neurodeck_full_save` (`storage.js:327-335`). Если ошибся с файлом, нажал не ту кнопку или принял чужую ссылку (по социальной инженерии), отменить нельзя. Рекомендация: перед импортом класть снапшот в отдельный ключ (`neurodeck_pre_import`, 1 шт.) и показывать тост «↩ Отменить импорт».

### M6. Remote-config в `main` мёртв — **воспроизведено в браузере**
`js/remote-config.js:138`: `root` — параметр внешней UMD-обёртки, в теле фабрики он **не виден**. Поэтому `typeof root === 'undefined'`, `fetchFn = null`, и в проде всегда возвращается `{applied:false, reason:'no-fetch'}` без телеметрии. В Chromium: при загрузке артефакт не запрашивается, `WEEKLY_MODS_REMOTE` не ставится. Юнит-тесты это не ловят: они либо передают `opts.fetch`, либо сами ждут `no-fetch`. В ветке `release/queue4-2026-10-01` это уже переписано через `globalThis`, но в `main` баг живёт.

Сопутствующая проблема: `sw.js` раздаёт `config/weekly-modifiers.v1.json` по схеме cache-first и без `?v=`, так что после починки обновления файла дойдут только при смене `VERSION`. Пока v1 — копия встроенного каталога, игрок разницы не видит. Риск в том, что «удалённая конфигурация» считается работающей.

### M7. На GitHub Pages публикуется весь репозиторий, и действует второй деплой без тестов
- `ci.yml:68-70`: `upload-pages-artifact` с `path: .`. Action исключает только `.git` и `.github`, поэтому публичными становятся `docs/` (в том числе хандоффы с путями VPS и «ssh vps»), `.opencode/` (промпты агентов и скиллы), `bot/`, `service/` (deploy-скрипт и пример env), `tools/`, `tests/` (около 2 МБ PNG-снапшотов), `AGENTS.md`. Секретов нет (скан чистый), но это лишняя поверхность и раздутый артефакт. Рекомендация: собирать whitelist-каталог (`index.html sw.js manifest.json css js fonts img config`). Живьём из песочницы не проверено: egress-политика режет `github.io`.
- **Пункт 1.6 всё ещё открыт.** На каждый push в `main` идут два деплоя: `pages build and deployment` (ветка) завершается за ~40 с, **до тестов**, а `CI + Deploy` деплоит только через ~9 мин после зелёных тестов (runs #278/#183 от 14:02 сегодня). Непротестированный коммит выходит в прод раньше CI.

### M8. Service worker: навигация network-first без таймаута
`sw.js:65-73`: `fetch(req)` для навигации без таймаута. На «флапающем» `github.io` (комментарий в самом `sw.js`) и в сетях РФ запрос может висеть десятки секунд, и всё это время игрок видит белый экран, хотя `index.html` лежит в кэше. Рекомендация: `Promise.race` с таймаутом 3–4 с и откатом на кэш.

## 4. Проверено и чисто

- **XSS:** пользовательские строки (карты, цели, задачи, герой) идут через `esc()`/`textContent`; в теле `dungeonConfirm` пользовательские поля экранированы; `esc()` внутри атрибутов `title="…"` используется только для констант каталога. CSP (`script-src 'self' + hash`) блокирует inline-обработчики даже при ошибке экранирования.
- **Импорт:** гварды `hasOwnProperty` на статах, предметы пересобираются из каталога `ARTIFACTS` (имя не берётся из файла), uid проверяется регэкспом, сейвы из будущей версии отклоняются.
- **State store:** читает через accessor (`shStoreSource`) — подозрение, что `applySyncData` оставит стору устаревшие ссылки, **не подтвердилось**.
- **Полный вайп:** «зомби»-восстановление из IDB после `fullWipeAll` **не воспроизводится** — сохранение на выгрузке затирает IDB пустым состоянием.
- **nd-config:** обход путей невозможен (регэксп имени), токен сравнивается timing-safe, есть лимит тела, сервис привязан к localhost.
- **Бот:** TLS проверяется (по умолчанию), токен только в env и в логи не попадает.
- **Секреты:** в репозитории токенов и ключей нет (IP `149.154.167.220` в скилле — публичный адрес API Telegram).
- **Миграции v7→v14** идемпотентны по устройству, битый `v` не реплеит миграции вниз.
- **A11y модалок:** фокус-ловушка, Escape, автофокус.
