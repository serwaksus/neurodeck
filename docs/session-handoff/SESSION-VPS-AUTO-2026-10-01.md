## Ключевые структурные изменения очереди (TL;DR владельцу)

1. **Схема сейва v13→v14** — единственный бамп, только в P11 (правило 18): персистентный подход
   недели `siege.approach`; миграция + sanitize + ре-пины storage-v8/regression-qa3 выполнены.
2. **State Store 2.0** (P17–P20, три шага): characterization-фиксация → редьюсеры sh/eco/siege +
   снапшот сейва из стора → UI-модуль Твердынь с доменными подписками. Поведение неизменно
   (characterization зелёные на каждом шаге), app.js −205 строк.
3. **Live-ops контур** (P14–P16): детерминированный weekly score → версионированные remote-config
   артефакты с safe-fallback → изолированный read-only сервис на VPS + opt-in приёмник телеметрии
   (DEFAULT OFF, публично не выставлен).
4. **Ощутимость и доступность** (P21–P22): аудио-микшер и game-feel анимации — строго по правилам
   19–20 (motion-гейты, без автозапуска звука).
5. **Расширенная e2e-матрица в CI** (P1–P2): browser-гейты кампании, responsive-gates
   (safe-area/короткий viewport/шрифт 200%), extended-visual; `test:e2e` вошёл в `npm run ci`.

## Rollback-заметки

| Что | Как откатить | Примечания |
|---|---|---|
| GitHub Pages (любой пакет) | `git revert <коммит>` + push | Деплой = push в main; визуальные регресии ловят extended-visual в CI |
| nd-config.service | `sudo bash service/nd-config/deploy.sh rollback [--purge-data]` | ~30 сек, прод-бота не касается; в клиентском пути сервис не участвует (клиент читает GH Pages, safe-fallback) |
