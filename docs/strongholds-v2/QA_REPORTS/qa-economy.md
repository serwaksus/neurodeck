## 3. Находки

### P1 — Рынок (+10% к доходу казны) не зачисляет золото: отчёт платит, казна — нет

- **Факт [F]:** `strongholdsDailyTick` (js/app.js:1589) зачисляет `gold += taxes + round(econ)` — множитель рынка (строка 1591 `income = round((taxes+econ)×(1+min(0.5;market)))`) существует **только в отчётной величине** `income`, в казну не попадает. Тот же разрыв в тосте «Тьма копила» (js/app.js:2790–2795 суммирует `tr.income`).
- **Воспроизведение [F]:** кампания 50 дней (6 захватов + Рынок + Амбары): UI-доход 72💰/день, факт-поступление 65💰/день; за 50 дней дыра **350💰 = 9.7% заявленного дохода** [F: campaign-days.json].
- **Паритет нарушен и против сима:** `tools/balance-lab/sim.js:432` — `st.gold += inc.taxes + inc.econ + inc.market` (фикс круга 3 «кран зачислен», BALANCE §1). Сим платит рынок, живой продукт — нет. Это прямой product≠sim parity break.
- **Эффект [E]:** экономика продукта беднее сбалансированной на ~10% при каждом активном Рынке (кап +50% при 5 рынках); UI и тосты систематически завышают доход. Темпы D1/G1 посчитаны симом с рынком — продукт в них не уложится.
- **Рекомендация:** зачислять рыночную надбавку в казну: `gold += income` вместо `gold += taxes + round(econ)` (или симметрично исключить market из `income`). Правка — в ведении dev; QA готово к ре-прогону харнеса.

### P2 — Призраки задач: списание −1💰/призрака не за «ночь», а однократно; кап 5💰/ночь недокументирован

- **Факт [F]:** `expireGhostTasks` (js/app.js:2102–2103, 2119–2122): штраф `Math.min(5; penaltyCount)` начисляется только в ночь перехода active→ghost; дальше призрак просто ждёт `ghostDays` (2/3/5 по tier) и исчезает без списаний.
- **SPEC §8:** «Призрак задачи (за ночь): −1» — без капа; UI-текст (js/app.js:2162): «−1 💰 за ночь, пока не изгонишь». Факт: 8 призраков → −5💰 (кап), ночь 2 → −0💰.
- **Эффект:** кран «призраки» ослаблен против спеки (страховка от прокрастинации дешевле заявленного); при 6+ призраках расхождение растёт. Гнев осады при этом честно считает всех живых призраков ×2 (js/app.js:1629) — т.е. осадное давление работает как в SPEC, а денежный кран — нет.
- **Рекомендация:** либо ночные списания по живым призракам (по SPEC), либо документировать кап 5 и одноразовость в SPEC §8 + тексте UI.

### P2 — Бесплатный «оплаченный день»: тотальная руина обнуляет upkeep и самовосстанавливается без трат

- **Факт [F]:** `SM.corruptionTick` (js/stronghold-model.js:111): `paid = gold >= upkeep`; при тотальной руине upkeep=0 → ночь «оплачена» при любой казне, все постройки +1 ступень (js/app.js:1593–1606 прокидывает gold дальше).
- **Воспроизведение [F]:** дефицит 31/день при доходе 7/день, wil 3: ночь 1–2 Целые, ночь 3 Обветшалые, ночь 5 Руина, **ночь 6: upkeep 0 → руины → Обветшалые, потрачено 0💰** (золото 0+7−0=7). Далее upkeep снова 31 → дефицит → цикл повторяется: руина фактически не держится дольше 1 ночи, стадии осциллируют руина↔обветшало без единой траты.
- **SPEC §6:** восстановление — за «оплаченный день» (списание содержания); «руина не ест» задумано как анти-спираль G2, но в комбинации даёт бесплатный ремонт каждые ~6 ночей.
- **Эффект:** девиация в пользу игрока; эффекты построек осциллируют ×0↔×0.5; баланс G2 (сим) это уже впитал (единый corruptionTick), так что паритет продукт↔сим НЕ нарушен — нарушена трактовка SPEC.
- **Рекомендация:** считать «оплаченным» только день с реальным списанием (`upkeep > 0`), либо зафиксировать осцилляцию в SPEC §6 как фичу анти-спирали.

### P3 — Спектакль осады всегда показывает «Оборона держит!», даже когда твердыня пала

- **Факт [F]:** js/app.js:1677–1678 читают `anyFell` до объявления (1684–1685): hoisted `var` = `undefined` в момент чтения → полноэкранный текст всегда «🛡 Оборона держит!». Воспроизведено браузером: `showSiegeReport([{held:false,…}])` → текст «Оборона держит!». Модальный отчёт (строки ниже) при этом корректен.
- **Рекомендация:** перенести вычисление `anyHeld/anyFell` выше формирования `spect`.

### P3 — Содержание стартового лагеря (sh01 без захвата) невидимо в сводке казны

- **Факт [F]:** `strongholdsDailyTick` тикает sh01 даже без `captured` (js/app.js:1594 — пропуск только для `i !== 0`), а `shUpkeepPerDay`/`shIncomePerDay` (js/app.js:1800, 1816) считают только захваченные → UI-содержание 0 при реальном списании. Воспроизведено: sh01 не захвачен, Ж1 построена → `shUpkeepPerDay()=0`, ночь списала 3💰 (1000→997).
- **Эффект:** на онбординг-окне (SPEC §9: Ж1 строится до первого захвата) дрейф −3💰/день невидим. Суммы малы, окно короткое.
- **Рекомендация:** учитывать sh01 в `shUpkeepPerDay` при наличии построек (или показать пометку «лагерь»).
