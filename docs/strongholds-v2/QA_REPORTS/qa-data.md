## Находки

### P2-1. export-json — неполный бэкап; импорт export-json через syncModal стирает твердыни/армию/осаду/сезон
- **Evidence (B10):** captured до=2 → после=0; season 2 → 1.
- `exportJson()` (app.js:2320) экспортирует только hero/stats/forged/goals/inventory/xpHistory. Импорт файла через `importSyncFile` → `applySyncData` → `migrateSyncData` считает `v` отсутствующим (=4) и MIGRATIONS[8] **пересоздаёт пустые** strongholds/army/siege, MIGRATIONS[9] — Сезон 1. Пользовательский сценарий «экспортировал JSON → импортировал» теряет LIVE-прогресс Твердынь v2.
- **Рекомендация:** либо включить в exportJson весь buildSyncData(), либо при import файла без `v`/`strongholds` не применять синтезированные миграциями разделы. Полный бэкап сегодня — только «💾 Скачать» (.ndsync) — работает байт-в-контент (B11).

### P2-2. Мульти-вкладка: выгрузка живой вкладки затирает записи другой вкладки
- **Evidence (B12b):** A записала gold 777 при живой B (in-memory 65); B после reload показывает 3210 — своё старое состояние.
- `beforeunload → saveGameState()` (app.js:2885) без проверки `savedAt` чужой записи: последняя **выгрузка** побеждает, изменения, сделанные в другой вкладке за жизнь сессии, теряются. Fresh-вкладка видит последнее корректно (B12 OK).
- **Рекомендация:** перед записью сравнивать `savedAt` в localStorage с моментом последнего чтения и предупреждать/мержить (сейчас защита есть только для облака).

### P2-3. newGameKeepCards: stale-хедер прогресса твердынь
- **Evidence (B14):** header сразу=«2/20», после `updateStrongholdProgress()`=«0/20». Данные сброшены корректно (captured=0, сейв 0/20) — чисто дисплейный баг: в render-списке функции нет `updateStrongholdProgress()` (app.js:3235+).

### P3-1. fullWipeAll не сбрасывает сезон
- **Evidence (B15):** после полного вайпа season.num=2 (был 2), start/snapshot сохранены. Весь остальной прогресс сброшен. Возможно «сезон глобален» by design — но тогда это стоит зафиксировать в SPEC.

### P3-2. После full-wipe-all не возвращается онбординг/старт-колода
- **Evidence (B15):** `ever_saved=1` (saveGameState внутри вайпа при пустом FORGED) → условие app.js:3277 `!hasEverSaved() && FORGED.length===0` ложно → игрок с 0 карточек не получает старт-колоду; deepRecovery ничего не находит. Комментарий у app.js:2850 показывает, что этот риск известен для fresh install, но вайп его воспроизводит.

### Примечание (не находка): MIGRATIONS[7] выполняется только для входов v≤6
`migrateSyncData` при входе v7 идёт 8→9 — чистка легаси (shards/boss*/isHollow) для «настоящего» v7-сейва не запускается (она уже была сделана при переходе в v7). Мусорные поля из таких сейвов всё равно не попадают в состояние — санитайзеры/белые списки applySyncData отфильтровывают (проверено B4: в сейве нет `"shards"`). Покрыто тестами A2/A2b/B4.
