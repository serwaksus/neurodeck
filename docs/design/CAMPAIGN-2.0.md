## 1. Ветвящаяся карта (вместо sh01→sh02→…→sh20)

Каждая провинция после первого узла предлагает **2 пути**; захват любой ветки открывает фронт провинции.

```text
Провинция
  ├─ безопасный путь: слабее гарнизоны, ниже награда, дешевле содержание
  ├─ военный путь: сильный гарнизон, военные артефакты, бонус атаки
  └─ торговый путь (пров. 2 и 4): выше налог, дальше маршруты, дороже upkeep
```

- **Schema (добавка в STRONGHOLDS, обратимая):** `branch: 'safe' | 'war' | 'trade'`,
  `next: ['sh05', 'sh06']` (опционально; отсутствие = линейный порядок как сейчас).
- Торговые пути считаются по ГРАФУ (`next`-рёбра + смежность), не только по индексу —
  миграция `tradeRoutes()` с фоллбэком на старый подсчёт (пиннут в parity — обновить эталон там же).
- UI карты: развилки рисуются поверх существующего SVG-глейфа; reducer карт-слоёв не трогаем.

## 2. Идентичность провинций

| Пров. | Палитра фона | Угроза | Региональное правило | Босс-арка |
|---|---|---|---|---|
| 1 Хутора | зелень/дерево | волки-рейдеры | −10% upkeep | «Стая» — 3 волны малых фаз |
| 2 Крепости | камень/сталь | осадные башни | +1 слот здания | «Инженер» — фаза ломает 1 постройку |
| 3 Гнили | болото/кость | гниль | коррупция +1 день долга | «Гниль» — фазы лечат долг врага |
| 4 Пепел | лава/угль | жара | налоги +10%, upkeep +10% | «Пепельный владыка» — 3 фазы |

Правило провинции живёт в `PROVINCES[p].rule` (каталог) и применяется одной функцией-модификатором
в `stronghold-model.js` (чистой, тестируемой), не раскидывается по app.js.

## 3. Подготовка осады (мини-цикл перед воскресеньем)

1. **Разведка** (есть: тень за 50💰) — расширить: разведанная ветка показывает состав гарнизона.
2. **Выбор подхода**: Штурм (сила), Осада (−20% силы врага за неделю ожидания, но wrath +1), Хитрость (пров. 3).
3. **Осадные ресурсы**: лестницы/таран — расходники (новая валюта НЕ вводится; крафт из золота).
4. **Подтверждение** (уже есть прогноз сил) + явный показ worst-case потерь (attrition-формула из модели).

## 4. Боссы как кульминации

- Вступление (1 тост с лором) → фаза 1 → изменение правила → фаза 2 → reward-choice.
- Reward-choice: артефакт босса ИЛИ +1 венец сезона ИЛИ снятие 1 руины (решение в модалке итогов).
- Арт: game-icons уже есть (драконы/личи/демоны) — перевести 11 эмодзи-боссов на иконки (хвост из волны 0–3).

## 5. Эндгейм-ротация (после 20/20)

- Престиж-круги уже есть (`ascEnemyMult` +25%) — добавить еженедельные модификаторы правил
  (ротация из remote-config, фаза live-ops): «Неделя тумана», «Неделя жадности» и т.п.
- Weekly score: эффективность = захваты / потери гарнизона / дни нулевого золота (не голый спидран).

## 6. Content schema (единый источник для каталога)

```json
{
  "id": "sh07", "prov": 2, "name": "Златоград", "branch": "trade",
  "next": ["sh08", "sh09"],
  "gar": 181, "def": 99, "total": 280, "slots": 7, "tax": 22,
  "mods": { "incomeMult": 1.0, "upkeepMult": 1.0, "siegeMult": 1.0 },
  "boss": { "id": "b7", "phases": 2, "artifact": "amuletFocus", "loreKey": "boss.zlatograd" },
  "events": ["caravan", "goldRush"]
}
```

Валидатор схемы — расширение `tests/qa-data` (tools/playtest-data.cjs): каждая твердыня обязана
иметь branch/next-consistency (next-узел ссылается назад только на родителя), bosses — на существующие артефакты.
