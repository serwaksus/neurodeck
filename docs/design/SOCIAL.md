## 0. Красные линии (согласованы с задачей «общий фронт без PvP»)

1. **Без PvP**: игроки не атакуют, не грабят и не соревнуются друг с другом напрямую. Единственный
   «противник» — PvE-кампания, как сейчас.
2. **Без чата, трейда и свободного текста**: единственный пользовательский ввод — псевдоним
   (жёсткая серверная валидация). Всё остальное — серверные шаблоны.
3. **Всё opt-in, DEFAULT OFF** (принцип TELEMETRY.md §1): без явного включения игрок невидим для
   социалки и не отправляет ничего.
4. **Игра полностью функциональна без социалки**: любой сбой/недоступность/просрочка артефактов =
   соц-UI молча скрыт, поведением как сегодня (паттерн safe-fallback из remote-config).
5. **Псевдонимизация**: сервер не хранит Telegram ID, hash ID или иные идентификаторы личности —
   только псевдоним + счётчики недели.
6. **Ноль новых npm-зависимостей** (правило 21), vanilla JS на клиенте, vanilla Node на сервисе.
7. UI-правила 19–20 действуют и здесь: reduced-motion/eco-эквиваленты, никакого автозапуска звука.

## 1. Weekly Community Goal — «Общий фронт»

Еженедельная **кооперативная** цель всего сообщества против игры (не друг против друга).

- **Артефакт** `social/community-goal.vN.json` (по контракту P15: schema, version, checksum,
  expires): `{ week: {season, week}, goal: {metric, target, kind}, progress, tiers }`.
  Метрики — из того, что уже считает клиент: суммарные захваты недели, суммарный weekly score
  (P14), доля недель без руин. Пример: «Ополчение берёт 400 твердынь до воскресной осады».
- **Вклад**: opt-in игрок отправляет один недельный отчёт после закрытия недели (см. §4).
  Сервер капит вклад физическими максимумами (захваты ≤ 20, score ≤ 400 — потолки формулы P14),
  повторный отчёт той же недели = LWW, склейка по псевдониму.
- **Целевая планка**: детерминированно на сервере — прошлый факт × 1.1 (первые недели константа);
  цель всегда достижима сообществу прежнего размера и растёт вместе с ним.
- **Награда** (анти-power-creep — не сила, либо сила для всех одинаково):
  - базовый тир: косметика — бейдж/титул сезона в профиле Telegram-миниаппа (или строка в панели);
  - растянутый тир: общедоступный PvE-модификатор следующей недели («Неделя праздника», добрый)
    через УЖЕ существующий механизм `WEEKLY_MODS_REMOTE` (P15) — отдельная ветка каталога,
    приоритет над обычной ротацией только в эндгейме 20/20.
- Все участники получают одинаково; личного рейтинга и «лучших вкладчиков» нет.

## 2. Rival-репорты — «Летопись фронта»

Асинхронный дайджест вместо лидерборда: игрок узнаёт о войне «в целом», включая факты о других
командирах, но никогда — о сравнении «ты vs конкретный игрок».

- **Артефакт** `social/chronicle.vN.json` — серверный агрегатор собирает из отчётов:
  - «численность фронта»: сколько твердынь пало за неделю, сколько командиров в строю;
  - «методы войны»: распределение подходов (штурм/осада/хитрость) и подходов веток (safe/war/trade);
  - «судьбы недели»: 3–5 фактов вида «Командир ⟨псевдоним⟩ взял Пепельного владыку хитростью» —
    шаблоны на сервере, псевдоним opt-in, факт выводится только из счётчиков отчёта;
  - «рекорды»: самая осаждаемая твердыня недели, самый редкий артефакт боссов.
- Топ-N псевдонимов по weekly score — **опционально и только решением владельца**: это уже
  соревнование, до решения не проектируется.
- Клиент рендерит только строки из серверных шаблонов (никакого пользовательского HTML).
- UI: панель «Летопись» рядом с панелью сезона + недельный тост-дайджест (правило 19: без анимации
  в reduced-motion/eco).

## 3. Opt-in кооп — «Подмога» (запечатанные баффы)

Прямая взаимопомощь без передачи ресурсов между экономиками (трейд запрещён красной линией №2).

- **Механика**: игрок-отправитель «запечатывает» помощь — сервер выпускает одноразовую печать
  (код) с фиксированным рецептом из белого списка: «+2 наёмника в полевую армию»,
  «−10% attrition на один штурм», «+50💰 единовременно». Получатель активирует печать по
  Telegram deep-link (бот уже есть; клиент — miniapp, deep-links уже контур бота).
- **Запечатанность** = анти-абьюз: нельзя передать свои ресурсы/артефакты, только стандартные пакеты
  с сервера; экономики игроков остаются изолированными.
- **Лимиты**: 1 печать от игрока в день; у получателя ≤ 3 невскрытых печатей; один рецепт не
  стакается; печать живёт 7 дней (до закрытия недели).
- Экономика: печать стоит отправителю небольшое золото (доп. sink), рецепты калибруются так, чтобы
  суммарный вклад был ≤ 1–2% недельного дохода — социалка не становится доминирующей стратегией.
- **Фаза 2 (вне этого предложения)**: общий босс-рейд — сезонный босс с кумулятивным HP,
  «урон» = weekly score участников; требует калибровки баланса и отдельного решения.

## 4. Контур backend (мини-сервис по образцу nd-config)

- Отдельный unit `nd-social.service` (правило 17: прод-бот не трогаем, свой код-каталог, свой env,
  DynamicUser, ProtectSystem=strict, rollback-скрипт) — listener 127.0.0.1:8096.
- **Эндпоинты**:
  | Метод и путь | Поведение |
  |---|---|
  | `GET /healthz` | статус + версия |
  | `GET /social/community-goal.vN.json`, `GET /social/chronicle.vN.json` | версионированные артефакты, ETag/304, как P16 |
  | `POST /v1/social/report` | opt-in недельный отчёт (псевдоним + счётчики), токен, rate-limit, капы |
  | `POST /v1/social/seal` / `POST /v1/social/seal/redeem` | выпуск/активация печати, одноразовость |
- **Хранение**: JSONL с ротацией (паттерн телеметрии P16), агрегатор — таймерный tick внутри
  сервиса, публикует артефакты в каталог раздачи. Отчёты старше 8 недель удаляются.
- **Публичный доступ — отдельное решение владельца** (CONFIG-SERVICE.md §6): клиент живёт на
  GitHub Pages, до localhost:8096 ему не дотянуться. Варианты: (а) reverse-proxy + TLS + домен,
  (б) публикация готовых артефактов в репо (GH Pages) еженедельным скриптом с VPS — тогда работают
  «Общий фронт» и «Летопись» в read-only режиме, а «Подмога» (write-эндпоинты) отпадает до
  полноценного канала. Никаких прокси не настраивать до решения.

## 5. Клиентский контур (без миграции схемы сейва)

- `js/social.js` (NDSocial, UMD): загрузка артефактов через проверенный лоадер remote-config
  (checksum/expiry/tamper/сеть → пустой результат → соц-UI скрыт), SW-кэш по контракту пинов.
- Настройки: секция «Сообщество» в модалке настроек — выключено по умолчанию, выбор псевдонима,
  предпросмотр того, что будет отправляться (только счётчики). Хранение — localStorage
  `neurodeck_social` (паттерн аудио-микшера P21): **схема сейва v14 не трогается**, правило 18
  не задействуется.
- UI-точки: строка прогресса «Общий фронт» в панели сезона, панель «Летопись», кнопка «Запечатать
  подмогу» в панели подготовки осады (P10). Всё — за typeof-гварды и eco/reduced-motion гейты.
- Отчёт отправляется один раз, после воскресного тика, только при opt-in; при недоступности
  сервиса отчёт просто не уходит (никаких ретраев через неделю — вклад пропущен, это честно).

## 6. Анти-абьюз и модерация

- Псевдоним: whitelist `[a-zA-Zа-яА-Я0-9 −]`, 3–16 символов, серверный реджект остального +
  серверный список стоп-слов (минимальный, пополняется по фактам).
- Вклады: серверные капы по физическим максимумам недели (§1); одна неделя — один отчёт на
  псевдоним (LWW); псевдонимы без капчи не создают рейтинга, атаковать нечего.
- Печати: выпускает только сервер, redeem одноразовый (атомарно), лимиты §3.
- Ставки низкие (PvE-кооп, награды косметические или общие) — мотивация мультиаккаунтов минимальна;
  при желании владельца позже — привязка псевдонима к initData бота (уже отдельное решение о данных).

## 7. Гейты для будущей реализации (когда владелец скажет «да»)

| Слой | Гейт |
|---|---|
| Модель/агрегация | чистые функции (таргет цели, капы, шаблоны летописи) + юнит-тесты |
| Клиент | fallback-матрица P15: valid/broken/expired/tampered/offline → UI скрыт |
| e2e | opt-in флоу, скрытие по умолчанию, redeem печати, отчёт после тика |
| CI | полный `npm run ci`; visual-базлайны — только осознанным регеном с причиной в коммите |
| Ops | runbook по образцу CONFIG-SERVICE.md (установка, проверка, rollback) |

Оценка объёма: «Общий фронт» + «Летопись» (read-only, вариант б) — M; «Подмога» и write-канал
с публикацией наружу — L (домен/TLS/прокси, rate-limits, модерация).

## 8. Риски

- **Публичный endpoint = новая поверхность атаки**: rate-limits, валидация размера/JSON, никаких
  IP в логах по умолчанию (паттерн P16). До публикации — риск нулевой (localhost).
- **Социальное давление на одиночек**: всё отключаемо одним тумблером, награды не дают силы,
  летопись не сравнивает с конкретным игроком.
- **Модерация псевдонимов** остаётся ручной (стоп-слова); полный ответ — только шаблоны сервера.
- **Операционная нагрузка**: ещё один сервис на VPS; главный риск — время владельца, не железо.

## 9. Что нужно от OWNER до любого кода (правило 22)

1. Делаем ли социалку вообще, и с каким приоритетом против IA-перестройки Today Loop и физической
   device-сертификации?
2. Канал: публикация сервиса наружу (домен/TLS/reverse-proxy) или read-only вариант «артефакты в
   репо» (без «Подмоги»)? Промежуточного по умолчанию не делаем.
3. Данные: подтверждение набора «псевдоним + счётчики недели, 8 недель хранения, без ID».
4. Награда «Общего фронта»: косметика, общий PvE-модификатор или оба тира (§1)?
5. Топ-N псевдонимов в «Летописи»: да/нет (граница с соревнованием).
6. Тон и терминология летописи (примеры шаблонов — на согласование).
