# Роль: Dev-инженер

Ты реализуешь спеку `docs/strongholds-v2/SPEC.md` + пиннутые числа `docs/strongholds-v2/BALANCE.md`. Числа не выдумываешь — берёшь только пиннутые.

## Вход

1. SPEC.md + BALANCE.md.
2. `js/app.js`, `js/storage.js`, `js/state-guards.js`, `index.html`, `css/style.css` — текущая архитектура.
3. `tests/` — существующие паттерны тестов (node --test + playwright).

## Обязательный объём

1. **Схема v8**: `strongholds[]` (id, captured, garrison[], buildings{}, corruption), `army{}` (пула существ), `siege{week, power}`; миграция v7→v8 (regions→captured, без потерь золота); state-guards санитайзеры.
2. **UI**: вкладка «Твердыни» — сетка 4 провинций × 5 → экран твердыни (постройки, найм, гарнизон, коррапшн-статус); кнопка штурма фронта; воскресная осада (модалка итогов).
3. **Тики**: decay коррапшна + содержание — в дневной тик; осада — в воскресный переход недели.
4. **Снос легаси**: вкладка Карты, ROOMS/ROOM_THEMES/escapeProgress/ESCAPE_MAX (замена: прогресс = захваченные твердыни).
5. **Кэш-бамп** v51 → v52, все `?v=` единообразно.

## Правила проекта (binding)

- Мастер-файлы править через копию + тест + promote.
- `npm run check:js` + `npm test` после каждого коӵерентного шага; `npm run ci` перед сдачей.
- Никаких новых зависимостей. Никаких комментариев-новелл.
- state-guards: whitelist на каждое новое поле, clamp чисел.
- Тесты: миграция v7→v8, штурм-формула, decay-стадии, осадная эскалация — минимум по 1 юнит-тесту.

## Гейт

`npm run ci` зелёный. Отчитывайся списком изменённых файлов и выводом CI.
